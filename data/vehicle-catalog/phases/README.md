# Three-phase roster pilot

The 660 historical rows are candidate identities, not verified specifications or completed cars. Do not add their count to the runtime roster. `progress.json` is a baseline-specific reconciliation snapshot: confirmed mappings are distinguished from suggestions and unresolved rows. Finished staged cars that have no matching historical identity are recorded separately; future slot replacement requires identity review, not automatic target inflation.

Phase 1: select an unresolved candidate, inspect actual runtime provenance/aliases, resolve year/market/trim, and record primary source anchors plus explicit simulation estimates. `pilot-01-research.json` contains the first two reviewed variants: US2024 Impreza Base2.0 and RS2.5. Their engines, masses and equipment differ materially. Do not create a duplicate Sport2.0 merely for cosmetic equipment.

Phase 2: `node scripts/car-catalog-placeholder-pilot.mjs` adds the two entries only when absent. It refuses overwrites and duplicate IDs. Artwork references come from RTG-001; no artwork documents, tuning, transmissions, physical profile or collision geometry are copied from RTG-001. Per-variant tuning is authored from source anchors and labeled estimates. Native CVT remains continuous, not eight fixed gears. Metadata and descriptions explicitly identify shared placeholder art and pending independent driving/original art.

Phase 3: replace only each candidate's graphics references with reviewed original art, calibrate the fitted cockpit/wheel placement, rerun roundtrip/handling/keyboard/touch QA, then update acceptance metadata. Never replace existing finished art with placeholders.
